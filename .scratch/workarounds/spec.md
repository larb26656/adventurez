# Workarounds: หน้ารวม บทความ และหน้า tag แบบ SSG

Status: resolved

## Problem Statement

ผู้เขียนต้องการแยกบันทึกวิธีทำหรือวิธีแก้ที่นำไปใช้จริงออกจาก Cheatsheet ซึ่งเป็นเอกสารอ้างอิง ปัจจุบันตัวอย่างการสร้างผู้ใช้และกำหนดสิทธิ์ PostgreSQL ฝังอยู่ท้าย Cheatsheet ทำให้ไม่มีที่รวม Workaround สำหรับค้นหา เปิดอ่านเป็นเรื่อง ๆ หรือเรียกดูตาม tag โดยยังต้องการให้ Astro สร้างหน้าแบบ static ทั้งหมด

## Solution

ผู้เขียนเพิ่ม Workaround ได้ด้วยเอกสาร MDX หนึ่งเรื่องต่อหนึ่งไฟล์ พร้อมชื่อ คำอธิบาย tag และวันเผยแพร่; เนื้อหาเขียนอิสระ ผู้เข้าชมเปิดหน้ารวมที่มีการ์ดและช่องค้นหา กดอ่านหน้ารายละเอียดหรือกด tag เพื่อดูเฉพาะเรื่องใน tag นั้นได้ หน้า tag มีช่องค้นหาของตัวเอง บทความ PostgreSQL เดิมย้ายมาเป็นเรื่องแรก โดยลิงก์เก่ายังพาไปยังลิงก์ของเรื่องใหม่ Astro สร้างหน้ารวม หน้า tag และหน้ารายละเอียดตอน build; การค้นหากรองข้อมูลที่เตรียมไว้ใน browser โดยไม่ใช้ API runtime

## User Stories

1. As a ผู้เขียน, I want to จดวิธีทำที่ใช้จริงเป็น Workaround แยกจาก Cheatsheet, so that เนื้อหาแต่ละชนิดมีที่อยู่ชัดเจน
2. As a ผู้เขียน, I want to เพิ่ม Workaround ด้วยเอกสาร MDX หนึ่งไฟล์ต่อเรื่อง, so that เพิ่มเรื่องใหม่ได้โดยไม่แก้รายการหน้ารวมด้วยมือ
3. As a ผู้เขียน, I want to เขียนรายละเอียดแบบอิสระ, so that จดวิธีไว้ได้แม้ไม่ได้เริ่มจากปัญหา
4. As a ผู้เขียน, I want to ใช้ code block และองค์ประกอบ MDX ที่มีอยู่, so that บันทึกขั้นตอนเชิงเทคนิคได้เหมือนเอกสารปัจจุบัน
5. As a ผู้เขียน, I want to ใส่ชื่อและคำอธิบายสั้น ๆ ให้แต่ละเรื่อง, so that ผู้อ่านเห็นบริบทก่อนเปิดรายละเอียด
6. As a ผู้เขียน, I want to ใส่ tag ได้หลาย tag ต่อเรื่อง, so that เรื่องหนึ่งเข้าถึงได้ผ่านหัวข้อที่เกี่ยวข้องทั้งหมด
7. As a ผู้เขียน, I want to ใส่วันเผยแพร่ครั้งแรก, so that ลำดับล่าสุดก่อนคงที่แม้แก้เนื้อหาในภายหลัง
8. As a ผู้เขียน, I want to ได้ข้อผิดพลาดตอน build เมื่อข้อมูลบังคับไม่ครบหรือ tag ที่สร้าง URL เดียวกันชนกัน, so that ไม่เผยแพร่รายการหรือหน้า tag ที่ผิดพลาด
9. As a ผู้เข้าชม, I want to พบ Workarounds ในเมนูหลัก, so that เปิดหน้ารวมได้โดยตรง
10. As a ผู้เข้าชม, I want to เห็นชื่อ คำอธิบาย tag และลิงก์รายละเอียดบนการ์ด, so that เลือกเรื่องที่ต้องการอ่านได้
11. As a ผู้เข้าชม, I want to เห็นเรื่องที่เผยแพร่ล่าสุดก่อน, so that พบเนื้อหาใหม่ได้ง่าย
12. As a ผู้เข้าชม, I want to ค้นหาชื่อเรื่องและคำอธิบายสั้น ๆ ในหน้ารวม, so that พบ Workaround ที่เกี่ยวข้องโดยไม่เปิดทีละเรื่อง
13. As a ผู้เข้าชม, I want to เห็นสถานะไม่พบผลลัพธ์เมื่อค้นหาไม่เจอ, so that รู้ว่าคำค้นปัจจุบันไม่มีเรื่องที่ตรงกัน
14. As a ผู้เข้าชม, I want to กดการ์ดเพื่ออ่านบทความแยก, so that อ่านขั้นตอน โค้ด และคำแนะนำได้ครบ
15. As a ผู้เข้าชม, I want to กด tag บนการ์ดหรือหน้ารายละเอียด, so that เห็นเฉพาะ Workaround ของ tag นั้น
16. As a ผู้เข้าชม, I want to ค้นหาภายในหน้า tag, so that จำกัดผลลัพธ์อยู่ในหัวข้อที่เลือก
17. As a ผู้เข้าชม, I want to เปิดหน้า tag ที่มี URL ของตัวเอง, so that แชร์หน้ารายการเฉพาะหัวข้อได้
18. As a ผู้เข้าชม, I want to เปิดหน้ารวมและหน้ารายละเอียดที่สร้างไว้ล่วงหน้า, so that อ่านได้โดยไม่พึ่ง API ที่ทำงานตอนเปิดหน้า
19. As a ผู้เข้าชมที่มีลิงก์เก่า, I want to เปิดลิงก์หัวข้อ PostgreSQL เดิมแล้วพบทางไปบทความใหม่, so that ลิงก์ที่บันทึกหรือแชร์ไว้ยังมีประโยชน์
20. As a ผู้เขียน, I want to ย้ายเนื้อหา PostgreSQL ไปไว้แห่งเดียวและเหลือเพียงลิงก์นำทางที่เดิม, so that ไม่ต้องดูแลเนื้อหาซ้ำสองชุด
21. As a ผู้เขียน, I want to ใช้ tag PostgreSQL สำหรับเรื่องที่ย้ายมา, so that ตัวอย่างแรกปรากฏในหน้า tag ที่ตรงเรื่อง

## Implementation Decisions

- ใช้คลังเอกสาร Starlight/MDX เดิมสำหรับหน้ารายละเอียด และใช้หน้า Astro แบบ static สำหรับหน้ารวมกับหน้า tag; ไม่สร้าง backend หรือ API ใหม่
- สัญญาข้อมูลขั้นต่ำต่อ Workaround คือ `title`, `description`, `tags` ที่ไม่ว่าง และ `publishedAt` ซึ่งหมายถึงวันเผยแพร่ครั้งแรก บังคับเฉพาะ Workaround ไม่บังคับ Cheatsheet หรือเอกสารประเภทอื่น
- ใช้ทางเข้า `/workarounds/` สำหรับหน้ารวม, `/workaround/<slug>/` สำหรับหน้ารายละเอียด และ `/workarounds/tags/<tag>/` สำหรับหน้า tag; tag มีหน้าเฉพาะเมื่อถูกใช้จริง ไม่ต้องมีหน้ารวม tag แยก
- อ่านเอกสาร Workaround ผ่าน collection ตอน build เพื่อสร้างข้อมูลการ์ดและชุด tag; สร้างหน้า tag จาก tag ที่พบโดยอัตโนมัติ กรณี tag ต่างชื่อแต่แปลงเป็น URL เดียวกันต้องแจ้งข้อผิดพลาดตอน build
- tag กำหนดใน metadata ของเรื่อง เปลี่ยนชื่อ tag แล้ว URL เปลี่ยนตามได้ ไม่ทำระบบ alias หรือรหัส tag แยก
- เรียงการ์ดตาม `publishedAt` ล่าสุดก่อนด้วยลำดับรองที่คงที่เมื่อวันที่เท่ากัน การแก้เนื้อหาไม่เปลี่ยนวันเผยแพร่
- หน้ารวมและหน้า tag ใช้ส่วนแสดงการ์ด/ค้นหาร่วมกัน โดยส่งข้อมูลที่สร้างไว้ตอน build ให้ฝั่ง browser กรองจากชื่อและคำอธิบายสั้น ๆ หน้า tag กรองเฉพาะสมาชิกของ tag ตั้งแต่ต้น ไม่ค้นในเนื้อหาเต็ม
- tag บนการ์ดและในรายละเอียดนำไปหน้า tag ได้ ไม่มีลิงก์ย้อนกลับไป Cheatsheet เพราะเป็นคนละประเภทเนื้อหา
- ย้ายหัวข้อ PostgreSQL ทั้งเนื้อหาและองค์ประกอบ MDX ไปเป็น Workaround เรื่องแรก ติด tag `PostgreSQL` และลงวันที่เผยแพร่ตามวันที่ย้ายขึ้นหน้าใหม่ เหลือหัวข้อพร้อมลิงก์ไปหน้าใหม่ใน Cheatsheet โดยรักษา fragment ของลิงก์เดิม
- เพิ่ม Workarounds ในเมนูหลัก และใช้ศัพท์ตาม glossary: Cheatsheet คือเอกสารอ้างอิง, Workaround คือบันทึกวิธีทำหรือวิธีแก้ที่ใช้จริงโดยไม่จำเป็นต้องเริ่มจากปัญหา

## Testing Decisions

- จุดทดสอบหลักที่ผู้ใช้ยืนยันคือเว็บ static ที่ Astro build แล้ว: เปิดหน้ารวม ค้นหา กด tag ค้นหาภายใน tag เปิดรายละเอียด และตามลิงก์เก่าที่มี fragment; ตรวจผลลัพธ์ที่ผู้ใช้มองเห็น ไม่ทดสอบเพียงการส่ง props หรือรายละเอียดการจัดการ collection
- ตรวจหน้ารวมเมื่อมีหลายเรื่องที่วันที่เผยแพร่ต่างกันและเท่ากัน เพื่อยืนยันลำดับล่าสุดก่อนและลำดับรองที่คงที่; ตรวจคำค้นจากชื่อ คำอธิบาย ไม่พบผลลัพธ์ และเรื่องที่อยู่นอก tag
- ตรวจ build ที่มีข้อมูล Workaround ไม่ครบ, ไม่มี tag, และ tag ที่แปลงเป็น URL ชนกันว่าแจ้งข้อผิดพลาด แทนการสร้างหน้าบางส่วนแบบเงียบ ๆ; ไม่ทำให้เอกสารประเภทอื่นถูกบังคับใช้กฎเดียวกัน
- ตรวจว่าหน้ารายละเอียดแสดง code block และองค์ประกอบ MDX ที่ย้ายมาได้ และ fragment เดิมยังนำไปยังลิงก์หน้าใหม่
- ก่อนหน้านี้ repo มี Vitest + Playwright สำหรับ Storybook stories ของ component แต่ยังไม่มีชุดทดสอบหน้า Astro ที่ build แล้ว; ใช้ Playwright หรือ smoke แบบ browser กับผล build เป็น precedent ด้าน browser runner โดยไม่เพิ่มชุดทดสอบเชิงโครงสร้างของ implementation

## Out of Scope

- โหวต ความเห็น บัญชีผู้ใช้ หรือข้อมูลที่เปลี่ยนได้โดยไม่ build ใหม่
- ค้นหาจากเนื้อหา MDX เต็มเรื่อง, ระบบค้นหา server-side, API สำหรับค้นหา
- ตัวกรองอื่นนอกจากค้นข้อความและการเปิดหน้า tag, หน้ารวม tag แยกต่างหาก
- โครงหัวข้อบังคับในเนื้อหา, ลิงก์บังคับกลับไป Cheatsheet, tag alias และ redirect ทั่วไปเมื่อเปลี่ยนชื่อ tag

## Further Notes

- ตัวอย่าง PostgreSQL ปัจจุบันมีหัวข้อ Workaround อยู่ท้าย Cheatsheet และมี `ChatMessage`; ลิงก์ fragment ที่ผู้ใช้ส่งมาคือกรณีรักษาความเข้ากันได้โดยเฉพาะ
- วันที่ของเรื่อง PostgreSQL ที่ย้ายมาคือวันที่เผยแพร่ Workaround ใหม่ ไม่ใช่วันที่ที่คาดเดาว่าเคยเพิ่มหัวข้อใน Cheatsheet
- แผนและจุดทดสอบผ่านการยืนยันในการสนทนา; spec นี้บันทึกข้อสรุป ไม่ใช่การลงมือ implement feature
