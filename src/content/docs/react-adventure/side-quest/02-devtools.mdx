## React DevTools

React DevTools เป็น browser extension ที่ช่วยให้คุณ inspect React component tree, debug state/props, และ analyze performance

## การติดตั้ง

### Chrome / Edge

1. ติดตั้งจาก [Chrome Web Store](https://chrome.google.com/webstore/detail/react-developer-tools/fmkadmapgofadopljbjfkapdkoienihi)
2. เปิด DevTools (F12) → จะเห็น tab **Components** และ **Profiler**

### Firefox

1. ติดตั้งจาก [Firefox Add-ons](https://addons.mozilla.org/en-US/firefox/addon/react-devtools/)

### Safari / Other browsers

ดูคำแนะนำที่ [React DevTools repository](https://github.com/facebook/react/tree/main/packages/react-devtools)

## Components Tab

### ดู Component Tree

เปิด DevTools → Components tab คุณจะเห็น:

```
▾ <App>
  ▾ <ProductList>
      <ProductCard />
      <ProductCard />
      <ProductCard />
  ▾ <Cart>
      <CartItem />
      <CartItem />
```

### Inspect Element

1. Click **เครื่องมือ select** (ด้านบนซ้าย) หรือกด `S`
2. Hover ไปบนหน้าเว็บ → DevTools จะ highlight component ที่เกี่ยวข้อง
3. Click → เลือก element นั้นใน tree

### ดู Props & State

Click ที่ component ใน tree → Panel ด้านขวาจะแสดง:

```json
{
  "props": {
    "name": "Wireless Mouse",
    "price": 599
  },
  "state": {
    "quantity": 2,
    "isHovered": false
  },
  "context": [...],
  "hooks": [...]
}
```

### Highlight Updates

เมื่อ component re-render, DevTools จะ highlight เป็นสีเหลือง/แดง:

- 🟡 Yellow = Component re-rendered
- 🔴 Red = Error occurred

เปิด/ปิดได้ที่ **Highlight updates when components render**

### เช็ค "ทำไม re-render?"

Click component → **Why did this render?** (ข้างใต้ state)

```
Render reason: "count" changed from 0 to 1
──────────────────────────────────────────
▸ <Counter> is not using memo
  • Parent re-rendered with different "count" prop
```

นี่คือวิธีหา performance bottleneck เบื้องต้น

## Profiler Tab

### เริ่ม Recording

1. Click **Profiler** tab
2. Click **Record** (วงกลมสีแดง)
3. ทำ action บนหน้าเว็บ (click, scroll, type)
4. Click **Stop** เมื่อเสร็จ

### rel: Flame Chart

Flame chart แสดง component tree ที่ถูก render ในแต่ละ commit:

```
Commit #12: "Add to cart clicked"
├── <App> (0.5ms)
│   └── <Navbar> (0.2ms)
│       └── <CartIcon> (0.1ms)
├── <ProductPage> (2.3ms)
│   ├── <ProductCard> (0.8ms)
│   ├── <ProductCard> (0.7ms) ← Rerendered
│   └── <ProductCard> (0.8ms)
├── <CartDrawer> (1.1ms) ← Rerendered
│   └── <CartItem> (0.4ms) ← Rerendered
```

### อ่าน Flame Chart

- **Width** = เวลาที่ใช้ render
- **Color**:
  - 🟦 Blue = Component render ปกติ
  - 🟨 Yellow = Component re-rendered (ควรดู)
  - 🟥 Red = Error/error boundary

### หา "Bottleneck"

1. หา commit ที่มี yellow/red หลายตัว
2. Click ที่ component ที่ re-render ผิดปกติ
3. ดูว่า "ทำไม re-render"

### Ranked Chart

Tab ที่สองคือ **Ranked** — เรียง component ตามเวลา render:

```
Most expensive components:
1. <ProductList>     12.4ms
2. <CartDrawer>       8.2ms
3. <ProductCard>      6.1ms  (×12 renders)
```

### ดู Component เฉพาะ

Click **focus** icon ข้าง component name เพื่อดูเฉพาะ component นั้น

## Common Use Cases

### Use Case 1: State ไม่ update?

1. เปิด Components tab
2. หา component ที่ควรแสดงค่าใหม่
3. ดู state panel — ค่าเปลี่ยนไหม?
   - **เปลี่ยน** = render ไม่ทำงาน → ดู React code
   - **ไม่เปลี่ยน** = setState ไม่ถูก → ดู event handler

### Use Case 2: Component re-render ผิดที่?

1. เปิด Components tab
2. เปิด "Highlight updates"
3. ทำ action ที่ทำให้ re-render
4. ดูว่า component ไหน highlight บ้าง
5. ถ้า highlight ผิดที่ → parent re-render กระทบ child

### Use Case 3: Performance ช้า?

1. เปิด Profiler tab
2. Record การใช้งาน
3. ดู Flame chart หา commit ที่ "หนัก"
4. Click component ที่ใช้เวลามาก
5. ดู "Why did this render?" → optimize

```json
      "deps": [1, "products"],
      "callback": "() => { ... }"
    }
  ]
}
```

ตรวจสอบว่า dependency array ถูกต้อง

## Practice: Debug Infinite Loop

มาฝึกใช้ DevTools debug infinite loop กัน:

```tsx
function BuggyComponent() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    setCount(c => c + 1) // infinite loop!
  })

  return <div>{count}</div>
}
```

### ขั้นตอน

1. เปิด DevTools → Components tab
2. กด **Record**
3. Run component → จะเห็น re-render ทันที
4. กด **Stop**
5. ดู Flame chart → commit มากมายจาก component เดียว
6. Click component → ดู state → count พุ่งไม่หยุด

### วิธีแก้

เพิ่ม empty dependency array:

```tsx
useEffect(() => {
  setCount(c => c + 1)
}, []) // ✅ Run ครั้งเดียว
```

## Keyboard Shortcuts

| Key | Action |
|-----|--------|
| `S` | Select element tool |
| `R` | Record/Stop |
| `0-9` | Speed up/slow down replay |
| `↑↓` | Navigate component tree |
| `Enter` | Expand/collapse |

---

## Summary

| Tab | ใช้ทำอะไร |
|-----|-----------|
| **Components** | Inspect tree, ดู props/state, find rerender cause |
| **Profiler** | Measure render performance, find bottlenecks |

:::tip ประจำ
ทุกครั้งที่ component ทำงานผิด ลองเปิด DevTools ก่อน มักจะเจอคำตอบเร็วกว่าการ console.log
:::
