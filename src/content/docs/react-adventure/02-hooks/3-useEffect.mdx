`useEffect` ทำงานหลัง React วาดจอเสร็จ ใช้กับงานข้างเคียง เช่น แตะ DOM, ตั้ง timer, หรือเขียน `localStorage`

```tsx
// รูปร่างของ effect ไม่ได้เป็นไฟล์ในตัวอย่างฝึก
useEffect(() => {
  // ทำงานหลัง render
  return () => {
    // cleanup ก่อนทำงานรอบใหม่ หรือตอน component ถูกถอด
  }
}, [dependencies])
```

| dependency | เมื่อไหร่ทำงาน |
| --- | --- |
| ไม่ส่ง array | หลังทุกครั้งที่ render |
| `[]` | ครั้งเดียวหลัง mount |
| `[theme]` | หลัง mount และทุกครั้งที่ `theme` เปลี่ยน |

## ธีมของตัวอย่าง

ตัวอย่างฝึกจำ `'light' | 'dark'` ด้วย `useState` แล้วใช้ effect นี้แปะ class ที่ `<html>` พาร์ต 4 ของร้านชาทำแบบเดียวกันใน `ThemeProvider` เพื่อให้ Tailwind v4 เห็นคลาส `dark` และใช้กุญแจ `tea-shop-theme`

```tsx
  useEffect(() => {
    const root = document.documentElement
    root.classList.toggle('dark', theme === 'dark')
    localStorage.setItem('basics-theme', theme)
    return () => {
      root.classList.remove('dark')
    }
  }, [theme])
```

dependency มีแค่ `theme` เพราะบรรทัดใน effect อ่านแค่ตัวนี้ cleanup ถอดคลาส `dark` ตอนออกจากตัวอย่างนี้ เพื่อไม่ให้หน้ารวมของแอปฝึกค้างธีมมืด

## Cleanup

ถ้า effect ไปตั้ง `setInterval` หรือ `setTimeout` ต้องคืนฟังก์ชันเพื่อล้าง ไม่เช่นนั้น timer ยังยิงหลังผู้ใช้เปลี่ยนหน้า หน้าสั่งชามี timeout สั้นๆ ตอนส่งฟอร์ม แต่ตัวนั้นอยู่ในการกดปุ่ม ไม่ได้อยู่ใน effect จึงไม่ต้องล้างด้วย effect

<ChatMessage message="ถ้าใส่ state ลง dependency แล้วไป setState ตัวนั้นใน effect จะวนไม่จบ" avatarKey="blackCat" />

```tsx
// ตัวอย่างที่ห้ามทำ
useEffect(() => {
  setCount(count + 1)
}, [count])
```

`count` เปลี่ยน เลยรัน effect อีก แล้วก็เปลี่ยน `count` อีก ตัวอย่างธีมไม่ทำแบบนี้ effect เขียน `theme` ลง storage แต่ไม่ได้เรียก `setTheme` ข้างใน
