ตัวอย่างขั้นตอนสำหรับสร้าง user ให้ application ใช้งาน database โดยแทน placeholder ใน `<...>` ให้เป็นค่าจริงก่อนรัน SQL (เช่น `<database>` เป็น `my_database`) คำสั่งสร้าง user และ role ให้รันด้วย account ที่มีสิทธิ์จัดการ role

### Full access (อ่าน/เขียน)

#### 1. สร้าง role และ user แล้วอนุญาตให้เชื่อมต่อ database

```sql
-- สร้าง role สำหรับสิทธิ์อ่านและเขียน
CREATE ROLE <app_full_role> NOLOGIN;

-- สร้าง user สำหรับ application
CREATE USER <app_user> WITH PASSWORD '<app_password>';

-- ให้ user รับสิทธิ์จาก role แบบ full access
GRANT <app_full_role> TO <app_user>;

-- อนุญาตให้เชื่อมต่อ database
GRANT CONNECT ON DATABASE <database> TO <app_full_role>;
```

#### 2. เชื่อมต่อเข้า database แล้วกำหนดสิทธิ์ใน schema `public`

```sql
-- อนุญาตให้ใช้งาน schema
GRANT USAGE ON SCHEMA public TO <app_full_role>;

-- ให้สิทธิ์อ่าน เพิ่ม แก้ไข และลบข้อมูลในตารางที่มีอยู่
GRANT SELECT, INSERT, UPDATE, DELETE
ON ALL TABLES IN SCHEMA public
TO <app_full_role>;

-- ให้สิทธิ์ใช้งาน sequence ที่มีอยู่ เช่น sequence ของ SERIAL
GRANT USAGE, SELECT
ON ALL SEQUENCES IN SCHEMA public
TO <app_full_role>;

-- ให้สิทธิ์กับตารางที่สร้างใหม่โดย object owner
ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO <app_full_role>;

-- ให้สิทธิ์กับ sequence ที่สร้างใหม่โดย object owner
ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT USAGE, SELECT ON SEQUENCES TO <app_full_role>;
```

ถ้าต้องการให้ migration role สร้าง table หรือ object ใหม่ใน schema `public` ให้เพิ่มสิทธิ์นี้:

```sql
-- อนุญาตให้ migration role ใช้งาน schema และสร้าง object ใหม่
GRANT USAGE, CREATE ON SCHEMA public TO <migration_role>;

-- ไม่มี CREATE บน database แล้ว migration จะล้มเหลว
-- สิทธิ์นี้ให้สร้าง schema ได้ เช่น tool สร้าง schema เก็บตาราง migration
GRANT CREATE ON DATABASE <database> TO <migration_role>;

-- migration tool หรือ ORM อาจสร้าง temp table
-- ต้องมีสิทธิ์นี้หลัง REVOKE TEMPORARY จาก PUBLIC ในส่วน backup role
GRANT TEMPORARY ON DATABASE <database> TO <migration_role>;
```

### Read-only

#### 1. สร้าง role และ user แล้วอนุญาตให้เชื่อมต่อ database

```sql
-- สร้าง role สำหรับอ่านข้อมูลเท่านั้น
CREATE ROLE <reader_role> NOLOGIN;

-- สร้าง user สำหรับการอ่านข้อมูล
CREATE USER <reader_user> WITH PASSWORD '<reader_password>';

-- ให้ user รับสิทธิ์จาก role แบบ read-only
GRANT <reader_role> TO <reader_user>;

-- อนุญาตให้เชื่อมต่อ database
GRANT CONNECT ON DATABASE <database> TO <reader_role>;
```

#### 2. เชื่อมต่อเข้า database แล้วกำหนดสิทธิ์อ่านใน schema `public`

```sql
-- อนุญาตให้ใช้งาน schema
GRANT USAGE ON SCHEMA public TO <reader_role>;

-- ให้สิทธิ์อ่านตารางและ view ที่มีอยู่
GRANT SELECT ON ALL TABLES IN SCHEMA public TO <reader_role>;

-- ให้สิทธิ์อ่านตารางและ view ที่สร้างใหม่โดย object owner
ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT ON TABLES TO <reader_role>;
```

<ChatMessage message="ALTER DEFAULT PRIVILEGES มีผลเฉพาะ object ที่สร้างโดย role ซึ่งรันคำสั่งนี้ หากมีหลาย role เป็นผู้สร้างตาราง ให้รันคำสั่ง ALTER DEFAULT PRIVILEGES FOR ROLE ... แยกตามแต่ละ owner" avatarKey="whiteCat" />

### Backup role (สำหรับ pg_dump)

user นี้ใช้รัน `pg_dump` อ่านได้อย่างเดียว

#### 1. สร้าง role และ user แล้วอนุญาตให้เชื่อมต่อ database

```sql
-- สร้าง role สำหรับสำรองข้อมูล
CREATE ROLE <backup_role> NOLOGIN;

-- สร้าง user สำหรับรัน pg_dump
CREATE USER <backup_user> WITH PASSWORD '<backup_password>';

-- ให้ user รับสิทธิ์จาก role สำหรับ backup
GRANT <backup_role> TO <backup_user>;

-- อนุญาตให้เชื่อมต่อ database
GRANT CONNECT ON DATABASE <database> TO <backup_role>;
```

#### 2. เชื่อมต่อเข้า database แล้วกำหนดสิทธิ์อ่านใน schema `public`

```sql
-- อนุญาตให้ใช้งาน schema
GRANT USAGE ON SCHEMA public TO <backup_role>;

-- ให้สิทธิ์อ่านตารางและ view ที่มีอยู่
GRANT SELECT ON ALL TABLES IN SCHEMA public TO <backup_role>;

-- pg_dump อ่าน last_value, is_called ด้วย SELECT
-- ไม่มีสิทธิ์นี้จะขึ้น permission denied for sequence
GRANT SELECT ON ALL SEQUENCES IN SCHEMA public TO <backup_role>;

-- ครอบคลุมตารางและ sequence ที่ <table_owner> สร้างต่อจากนี้
ALTER DEFAULT PRIVILEGES FOR ROLE <table_owner> IN SCHEMA public
GRANT SELECT ON TABLES TO <backup_role>;

ALTER DEFAULT PRIVILEGES FOR ROLE <table_owner> IN SCHEMA public
GRANT SELECT ON SEQUENCES TO <backup_role>;

-- ทางลัด PostgreSQL 14+ แทน GRANT ด้านบน
-- GRANT pg_read_all_data TO <backup_role>;
```

#### 3. ถอน TEMP จาก PUBLIC แล้วคืนให้ role ที่ต้องใช้

```sql
-- PUBLIC ได้ TEMPORARY บน database เป็นค่าเริ่มต้น
-- ทุก user รวม <backup_user> จึงสร้าง temp table ได้
-- Databasus เตือน 'Current user has the following write privileges: TEMP'
-- ไม่ใช่ INSERT, UPDATE, DELETE บนตารางจริง แต่ทำให้ backup user ไม่ได้ read-only จริง
-- การถอนมีผลกับทุก user
REVOKE TEMPORARY ON DATABASE <database> FROM PUBLIC;

-- คืน TEMP ให้ role ของ application เพราะคำสั่งด้านบนถอนจากทุกคน
GRANT TEMPORARY ON DATABASE <database> TO <app_full_role>;

-- <migration_role> ได้ GRANT TEMPORARY ไว้ในบล็อก migration role ด้านบน

-- ตรวจว่า <backup_user> สร้าง temp table ไม่ได้ ผลต้องเป็น false
SELECT has_database_privilege('<backup_user>', '<database>', 'TEMP') AS can_create_temp; -- should be false
```
